# 全プロジェクト共通の指示

## 設計は grilling で詰めてから書く

設計の判断を含む作業では、書き始める前に必ず `grilling` スキルを起動する。対象は、設計スキルの
作成、アーキテクチャ・データモデル・API・画面の設計など。

- 「〜を書いて」「〜を設計して」と実装まで頼まれても、設計の判断を含むなら先に詰める。
  小さく見える設計でも省かない。
- 事実(既存コードやスキルとの重なり、ライブラリの挙動)は自分で調べる。ユーザーには判断だけを聞く。
- ユーザーが認識が揃ったと確認するまで、実装・執筆に入らない。

## 標準の定義に従う

形式・用語・挙動(日時や通貨の形式、ID、HTTP のメソッドとステータス、エラーの形、認証の作法など)を
自分で決める前に、標準(RFC / ISO / IEEE / W3C / WHATWG / NIST など)が定義していないかを確かめる。
定義があれば、それに従う。

- 既存のコードや決まりが標準と食い違っていたら、黙ってどちらかに合わせない。食い違いを報告して
  判断を仰ぐ。
- どの標準が当てはまるか、現行版はどれかは `standards-compliance` スキルで確かめる。
