# 公開済みイベントのバージョニング

[ddd-domain-events](SKILL.md) 第 7 節の詳細。後方互換な変更の見分け方、
破壊的変更を新しい型で出す手順、永続イベントの読み替え、保存形式の決め方。

## 後方互換な変更と、そうでない変更

| 変更 | 互換 | 対応 |
| --- | --- | --- |
| **フィールドを追加**(既定値つき) | ある | そのまま足せる。古いハンドラは無視する |
| フィールドを**必須で追加** | **ない** | 既定値を付けるか、新しいイベント型へ |
| フィールドの**改名** | **ない** | 追加 → 両方書く → 古い方を消す(3 段階) |
| フィールドの**削除** | **ない** | 先に購読側を直してから消す |
| **意味の変更**(単位・基準を変える) | **ない**。最も危険 | **必ず新しい型にする**。形が同じなので気付けない |
| イベント名の変更 | **ない** | 新しい型を足し、両方発行する期間を作る |

**「意味の変更」が一番事故る。** `amount` を税込から税抜に変えても、型もフィールド名も
変わらないので、購読側は気付かずに動き続ける。

## 破壊的変更は「新しい型を足す」

**既存のイベントクラスを書き換えない。** 新しい型を作り、移行期間を設ける。

```python
@dataclass(frozen=True, kw_only=True)
class OrderPlaced(DomainEvent):          # 既存。消さない
    order_id: str
    total_amount: Decimal                # 税込だった


@dataclass(frozen=True, kw_only=True)
class OrderPlacedV2(DomainEvent):        # 新しい意味を持つ別の型
    order_id: str
    subtotal: Decimal                    # 税抜
    tax: Decimal
```

移行の順序:

1. 新しい型を追加し、**両方を発行する**。
2. 購読側を 1 つずつ新しい型へ移す。
3. 全部移り終えたら、古い型の発行を止める。
4. 永続化された古いイベントを読む必要がなくなったら、型を削除する。

**バージョンを表す `version` フィールドを持たせるより、型を分ける方が安全。**
型が違えば、購読側の分岐漏れが型チェックで見つかる。

## 永続イベントの読み替え

古い形式で保存された行を読むときは、**復元時に新しい形へ変換する**
(upcasting)。変換はイベントストア側(インフラ層)に置き、ドメインには
新しい形だけを見せる。

```python
def _to_domain(self, row: OutboxRow) -> DomainEvent:
    payload = json.loads(row.payload)
    if row.event_type == "OrderPlaced":          # 旧形式
        return OrderPlacedV2(
            order_id=payload["order_id"],
            subtotal=Decimal(payload["total_amount"]) / Decimal("1.1"),  # 当時の税率
            tax=...,
        )
    ...
```

- **変換に使う値は、当時の値をべた書きする**(上の税率)。現在のドメインロジックを
  呼ぶと、将来ロジックが変わったときに過去のイベントの解釈が変わる。
- 変換が増えて読めなくなったら、**一度データ移行して古い形式を消す**方が安い。

## ペイロードは安定した形で保存する

- **プリミティブで持つ**(`str` / `Decimal` / ISO 8601 文字列)。値オブジェクトを
  そのまま pickle しない。クラス定義を変えた瞬間に読めなくなる。
- **`Enum` は値(文字列)で保存する。** `name` や連番に依存しない
  ([ddd-state-transition](../ddd-state-transition/SKILL.md))。
- **未知のイベント型を受け取ったときの挙動を決める。** 無視するか、
  dead letter に送るか。黙って落とさない。
