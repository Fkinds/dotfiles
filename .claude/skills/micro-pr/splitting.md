# できあがった差分を分ける

[SKILL.md](SKILL.md) 第 7 節 B の詳細。実装を終えた大きな差分を、あとから PR に分けるときに読む。
分け方の規則(基準、量、切り方、順序)は SKILL.md のとおりで、ここは手順だけを書く。
行数のスクリプトは SKILL.md 第 2 節と同じもの(このスキルのディレクトリの
`scripts/count_pr_lines.py`)。

---

## 1. 最終状態を残す

分ける前の完成形を、名前の付いたコミットに残す。最後の照合(第 4 節)に使う。

```bash
git switch -c <機能名>/final         # 既にブランチにコミット済みなら、そのブランチを final とみなす
git add -A
git commit -m "分割前の最終状態"
```

- このブランチは push しない。コミットメッセージの規約を気にしなくてよい。
- 以下では、このブランチを `FINAL` と書く。

---

## 2. 計画を立てる

```bash
python3 <このスキルのディレクトリ>/scripts/count_pr_lines.py <trunk> FINAL -v
```

1. ファイルごとの行数を見て、ファイルを層と閉じた単位に振り分け、SKILL.md の計画の表を作る。
2. **複数の PR にまたがるファイル**に印を付ける。1 つのクラスで 500 行を超えるもの、
   シグネチャの変更(足す → 移す → 消す)がこれに当たる。
3. 表をユーザーに見せ、承認を得る。

---

## 3. 下の PR から順に作る

```bash
git switch -c <1 本目のブランチ> <trunk>     # gh stack なら gh stack init --base <trunk> <1 本目のブランチ>
git checkout FINAL -- <この PR のファイル>   # ファイルを丸ごと最終状態にする
git rm <FINAL で消えたファイル>              # 削除もこの PR に入るなら
```

- **複数の PR にまたがるファイル**は、この PR の時点の中身を書き起こす。最終状態から、
  上の PR で足す振る舞いとそのテストを除いたものになる。`git add -p` は対話式なので使えない。
- ファイルの移動は、新しいパスを `git checkout FINAL --` で取り出し、古いパスを `git rm` する。
  rename かどうかは差分を取るときに git が判定する。
- 品質チェックを流す。**通らなければ、この PR に足りない前提がある。** 上の PR のファイルを
  足して通すのではなく、計画の層の順序か、単位の振り分けを見直す。
- コミットの前に、作業ツリーの行数を確かめる。

  ```bash
  python3 <このスキルのディレクトリ>/scripts/count_pr_lines.py <1 つ下のブランチ>
  ```

- コミットしたら、次のブランチを積む(`gh stack add <次のブランチ>` か
  `git switch -c <次のブランチ>`)。

---

## 4. 最終状態と一致するか確かめる

一番上のブランチで、最終状態との差分が空になることを確かめる。

```bash
git diff FINAL HEAD --stat
```

- 差分が残っていたら、どこかの PR で取りこぼしたか、途中の状態の書き起こしを誤っている。
  どの PR に入れるべき変更かを計画の表で探し、その PR を直して上を積み直す
  (`gh stack rebase --upstack`)。
- 一致したら `FINAL` は要らない。消すのは、ユーザーに確かめてから。

---

## 5. つまずきやすいところ

| 症状 | 原因と対処 |
| --- | --- |
| 下の PR のテストが、上の PR のクラスを import して落ちる | テストの振り分けの誤り。そのテストは、テストする実装と同じ PR に移す |
| import の検査(import-linter など)が途中の PR で落ちる | 新しいモジュールを契約に足す変更が上の PR にある。そのモジュールを足す PR へ移す |
| 抽象にメソッドを足した PR で、既存の実装が抽象を満たさない | 抽象とすべての実装(テストのフェイクを含む)を同じ PR に入れる(SKILL.md 第 6 節) |
| 途中の状態のファイルが、どの PR の時点のものか分からなくなる | 計画の表に、またがるファイルごとに「どの PR で何を足すか」を書いておく |
